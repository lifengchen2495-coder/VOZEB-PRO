# 短剧工作台重做方案

核对日期：2026-09-09。范围：根据用户提供的 5 组 Skill，重整短剧模块的创作流程。用户随后确认“先搞流程，UI 后面再考虑”，本轮已实施流程基础与现有界面接入。前文保留改造前的问题分析和完整设计方向，实际完成范围见“本轮实施结果”。

## 改造方向

将当前“输入已有剧本，再拆镜和生成”的短剧生产线，升级为能从故事设定开始、逐步打磨并持续制作的工作台：

**故事设定 → 人物小传 → 分集节奏 → 剧本创作 → 分镜设计 → 视频制作。**

前四步建立可编辑、可采用、可追溯的创作产物，后两步衔接现有图片、视频、音频与合成设施。动态漫作为首个完整创作预设；题材、时长、制作方式和模型分别配置。

六个阶段是工作区导航，不是六次强制审批。有现成小说、剧本或分镜的用户，可在导入和必要校对后进入对应阶段。每一步都能返回修改，系统明确标出受影响的后续内容。

## 当前模块的实际基础

目前已有四阶段导航、剧集管理、剧本编辑与整本导入。内容分析从本集剧本提取角色、场景、道具、线索与镜头事实；视觉分析再补充生图、生视频提示词、首尾帧、运镜与连续性。现有角色资产、音色、生成任务、版本、费用、字幕、合成和剪映导出均值得复用。

不足集中在以下位置：

- 故事、人物动机、角色关系和节拍没有独立产物。项目简介、角色描述和本集大纲能够存文本，但不足以支撑有依赖关系的持续创作。
- 内容分析强调忠实提取，视觉分析禁止改镜头数量、剧情、对白和时长。两者均不适合直接承担剧情重构与编剧任务。
- Agent 有通用策划能力，但文本建议缺少回写人物、小传、节拍和剧本的结构化应用机制。
- 当前重新分析会重建镜头并重置关联媒体状态；剧本修改又缺少统一的派生产物过期机制，容易出现原稿、分镜与已有视频不一致。
- 叙事镜头与模型生成时长耦合较紧。更换模型不应直接改变作品的叙事结构。

这些是代码结构核对结论，不代表本轮实际运行了模型或验证了成片质量。

## 应调整的资料规则

| 原文中的规则或冲突 | 建议处理 |
| --- | --- |
| 编剧要求台词不超过 10 字，转分镜又要求不超过 20 字 | 作为对白风格建议；按角色语速、停顿和镜头时长检查可说完性，不机械截断对白 |
| 默认 3—5 分钟、800—1200 字，节奏表却只列到 180 秒 | 单集时长单独设定。剧本总字数包含动作说明，不能直接当成朗读时长；180—300 秒部分需按内容重新规划 |
| 0—30 秒铺垫、90—120 秒爆发 | 作为一种动态漫节奏预设。60 秒悬疑、情感短剧等应有独立节拍建议，不能等比例照抄所有节点 |
| 每集强动态最多 3 处 | 作为有限动画制作预算建议，不作为所有视频的硬限制；主体动作、运镜和特效复杂度分别描述 |
| 台词字数决定口型“微／中／大” | 不作为口型同步算法。声音与时长先按可用能力估计，生成语音后按真实音频校验；表达强度可保留为导演说明 |
| 每段都要写环境、背景与特效运动 | 按镜头需求补充，允许固定机位和静止背景，避免所有画面都被迫添加粒子、光影变化 |
| “100% 还原”与剧情反转、精简对白同时出现 | 项目选择改编策略，并标记不能改变的剧情、台词或人设；修改建议列出与原稿的差异 |
| Seedance 的固定秒数、文件数、真人素材限制 | 仅视为资料中的平台描述；上线前按实际接入的渠道、模型和模式核对，不上升为全站规则 |
| 首帧、角色参考和视频参考在同一示例中混用 | 根据目标渠道模式检查。当前特价版适配器明确禁止首尾帧与普通参考混用 |
| 改称 Figure 1／2 或替换敏感词以避免被拒绝 | 不纳入自动保证机制。换词不能证明权利或内容合规，也可能改变剧情事实；上游错误保留并解释 |
| A4、宋体、页边距和页码 | 作为文档导出样式，网页编辑不照搬纸张排版 |

此外，资料把“内景／外景”称为“景别”，产品字段应区分内外景与远景／中景／特写，避免分镜数据含义混乱。

## 新版界面与操作

统一布局：顶部为项目、集数和六阶段导航；左侧为当前阶段对象目录；中央为可编辑产物；右侧为可收起的阶段助手与修改建议。制作状态和版本状态分别显示。移动端目录和助手按需展开，中央产物始终可操作。

助手按当前阶段切换任务和上下文。用户看到“完善动机”“调整反转”“改写台词”等操作；Skill 名称、JSON、内部提示词和渠道细节只在有必要的高级设置中出现。

| 工作区 | 中央主要内容 | 左侧目录 | 主要操作 |
| --- | --- | --- | --- |
| 故事设定 | 一句话故事、类型、受众、世界规则、冲突、集数与时长、改编策略 | 原始资料与设定条目 | 从想法起稿、导入小说／剧本、比较并采用故事方案 |
| 人物小传 | 动机、弱点、秘密、行为、关系、成长、外貌与声音 | 人物列表 | 补全小传、检查行为逻辑、锁定特征、关联角色参考图 |
| 分集节奏 | 全剧分集概览；选中集的节拍与预计时间段、情绪变化、伏笔与回收 | 集数列表 | 调整节拍顺序、缩短铺垫、设计反转、检查集间衔接 |
| 剧本创作 | 按场次编辑动作、对白、旁白与声音说明；可查看原稿对照 | 集数与场次 | 按本集大纲起稿、选段改写、查看差异、采用建议 |
| 分镜设计 | 镜号、时长、场景、人物、景别、动作、台词、声音、转场和参考图 | 场次与镜头 | 从采用稿拆镜、拆分／合并、调整连续性、标注镜头用途 |
| 视频制作 | 生成片段清单、时间轴提示词、素材绑定、任务与结果、配音字幕与导出 | 片段／任务列表 | 生成提示词、生成选中片段、重试失败项、选择成片版本、合成与导出 |

内容校对就近出现：人物阶段检查动机，节奏阶段检查铺垫和回收，剧本阶段检查说话人和原稿差异，分镜阶段检查覆盖、连续性与时长。阻塞问题显示具体位置和修复动作；创作建议可以保留，避免每一步都形成模态对话框。

项目列表同步调整：卡片显示当前集、当前创作阶段及实际制作进度。导入入口提供“从想法开始”“已有小说”“已有剧本”，项目细节渐进填写，不在创建弹窗中一次要求填完所有小传字段。

角色、场景、道具和线索仍是项目共用资产，从相关工作区就近进入；小传中的叙事身份与角色视觉参考保持关联。版本、费用和素材管理作为项目工具保留，避免六阶段导航挤掉已有制作能力。

## 最关键的数据与交互变化

### 1. 创作产物必须有独立身份

建议在现有项目模型上增加创意简报、人物叙事档案、分集节拍、场次／剧本块和生成片段。优先做兼容扩展，字段命名与数据库落点在实施时统一确定。

每个可采用产物记录稳定 ID、内容版本、所依据的上游版本、来源、采用状态。生成任务另记排队／执行／成功／失败状态，已经成功的旧视频不因上游改稿变成“失败”。

模型输出使用结构化 Schema 校验，界面负责阅读和编辑；Markdown 作为导入、展示或导出格式。原始 Skill 及示例是参考资料，不具有覆盖项目规则或操作权限的资格。

### 2. 原稿、改编稿与制作稿可追溯

导入小说保持原始资料不变，改编稿记录来源区间。根据采用的人物与节拍生成剧本；再从采用稿提取分镜事实。沿用现有内容抽取的对白保真与来源覆盖检查，新增编剧阶段单独承担原创和改写。

为避免双重编辑源冲突，可逐步采用带稳定 ID 的场次／剧本块作为新版编辑源，按确定规则生成兼容 `episode.script`；导入旧纯文本时先保留原文并建立块映射。不要让两个独立可写副本各自演变。

### 3. 改上游，标记影响范围

示例：将林岚在一个场次的台词改短，应标记对应镜头的对白／音频／字幕、关联生成片段待更新；无需使其他角色参考图失效。若改变蓝色外套，则标记引用这套造型的镜头与片段。若修改动机，先检查相关节拍与场次是否需要调整。

依赖不确定时，可以扩大“需检查”的范围，但不删除历史结果。按需重新生成并采用新版本，保留旧版本及成本记录。

应用建议与后台任务完成回写均检查所依据的版本。用户已经改过同一产物时，旧结果进入候选，显示差异，不覆盖当前稿。局部应用在服务端原子校验与写入。

### 4. 分镜与生成片段分开

建议关系为 `Episode → Scene → StoryboardShot`；`GenerationClip` 引用一个或多个镜头及它们的时间范围。初期延续“一镜一片段”的兼容映射，后续再支持多镜头合为一次生成、长镜头分段生成。

例如：整集 60 秒，其中前 12 秒含 3 个叙事镜头。可以把这 3 个镜头编为一个 12 秒生成片段，也可分别生成后剪辑；选择取决于渠道能力和创作要求。12 秒只是示例，不是全站默认值。

片段必须有独立结果与镜头时间映射。合成按采用的片段及剪辑区间执行，避免 3 个镜头引用同一个 12 秒视频后被重复拼接 3 次。切换分组时保留原有任务与结果归属。

### 5. 提示词从正式产物编译

视频制作使用“采用的人物与场景设定 + 分镜时序 + 真实参考绑定 + 音画策略 + 模型能力”生成最终请求。故事事实、导演设计、供应商语法各有边界。

参考图的显示编号由稳定素材 ID 和最终提交顺序生成，不能只在文本中写 `@图片1` 而没有实际素材。按渠道支持处理首帧、尾帧、角色、场景、动作视频和声音参考；可导出面向外部平台的提示词与清单，但不把外部界面语法当成所有 API 都支持的协议。

提示词预览应与最终提交内容一致，避免用户修改后又被旧编译器重复追加大段描述。当前 Seedance 特价版还校验中文提示词长度，详细导演稿需保留，适配结果不足以表达时提示调整或拆段，不静默截去关键对白与动作。

声音策略在制作阶段明确：模型原生对白、后配音或静音；字幕优先复用现有后期能力。模型实际支持的输出决定可选动作，文字提示不能保证模型按要求生成声音或准确字幕。

## Skill 和 Agent 的接入方式

五组方法分别成为对应阶段的任务规则和参考库，补充项目策划任务。运行时只组合当前阶段需要的内容，并使用明确的数据输入和输出 Schema；不要每次向模型发送全部参考文档。

每次任务保存方法版本、相关输入快照、生成结果及采用关系，复用已有 Agent Run／任务追踪能力。后台修改 Skill 后，只影响新请求。人物、分集节拍、场次、镜头各有可验证的应用动作，复用现有用户权限与项目校验。

阶段助手负责提出修改方案，应用层负责版本比较、持久化及失效传播。已有明确的阶段生成动作可以直接产出候选；已经采用的正式稿通过差异应用更新。批量视频生产显示真实片段范围和可用的费用估算，沿用现有任务、计费和取消机制。

## 实施顺序与每步验收

整体设计一次确定，工程按可交付顺序实施；不建议只上线六个空标签，也不建议同一轮重写生成渠道和任务系统。

| 顺序 | 主要改动 | 完成标准 |
| --- | --- | --- |
| 1. 数据与回写基础 | 阶段产物、稳定 ID、版本依赖、局部应用、候选与采用状态；同步前后端白名单 | 保存再读取字段不丢；旧项目正常打开；旧结果不能覆盖新稿；重新分析不清空历史媒体 |
| 2. 新版创作工作台 | 六阶段壳、创建／导入入口、故事设定、人物小传、节拍、分场剧本、阶段助手 | 一个想法和一本已有文本均能进入合适阶段；完成一集可采用剧本；局部修改可追溯 |
| 3. 分镜与视频衔接 | 可编辑分镜、片段映射、Seedance 提示词与素材适配、制作区迁入 | 镜头与片段时长分别正确；素材引用完整；最终请求符合渠道约束；历史结果可继续使用 |
| 4. 完整体验验收 | 合成、字幕、导出、版本选择、失败恢复、桌面及移动端 | 改稿→局部更新→片段生成→合成／导出闭环；老项目和其他模块转入短剧的兼容回归通过 |

首轮功能样例以“一集 60 秒动态漫悬疑故事”贯通，另加已有剧本导入作为兼容样例；同时保留可配置时长和风格。先验证实际创作产物与修改行为，再扩展更多题材模板和长篇连续剧策略。

必要测试包括：Schema 与持久化往返、人物别名冲突、局部修改影响范围、并发版本冲突、上游变化后旧任务完成回写、镜头拆合与片段映射、对白覆盖、素材编号与请求一致、片段不重复合成、历史项目加载，以及导入—编辑—采用—制作的浏览器流程。真实文本和视频渠道另做小规模体验验收，评估人设、反转逻辑、可读性和生成可执行性，不把格式通过等同于作品质量通过。
