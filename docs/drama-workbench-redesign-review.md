# 短剧工作台流程与实施记录

核对日期：2026-09-09。用户提供 5 组剧本 Skill，随后明确“先搞流程，UI 后面再考虑”，并纠正默认操作应是“我给剧本，AI 自动分析”。本文件以这项最新要求为准。

## 当前主流程

**提供剧本 → AI 一键分析 → 查看／修正结果 → 分镜 → 视频制作。**

项目默认打开“剧本输入”，新建弹窗可直接粘贴原文，进入项目后也可用现有文件导入入口。故事简介、人物小传、节拍和分场表单均不是前置必填项。

一次点击自动完成五步：

1. 从全部已导入剧集原文提取故事梗概、核心冲突与事实。
2. 从全部已导入剧集原文提取人物、动机、关系与已交代的特征。
3. 分析当前集事件顺序、节拍、情绪与钩子。
4. 提取当前集场景、道具、对白和镜头事实。
5. 生成当前集分镜视觉方案，进入分镜页。

全剧故事和人物共用一份分析；节奏、拆镜和分镜方案处理当前选择的剧集。多集项目切换剧集后再分析该集。原文与分析结果均未变化时复用已有步骤；中途失败后再次点击会从尚未完成的步骤继续。

六个导航依次为“剧本输入、故事分析、人物分析、节奏分析、分镜设计、视频制作”。分析页默认显示可读报告，点击“编辑分析结果”才展开修订表单；“保存修订”直接应用结果。每页也可单独重新分析。分镜完成后可核对镜头内容或进入制作；图片、视频、音频任务仍由用户在制作流程中发起。

## 分析与原稿的边界

- 新分析动作仅支持故事、人物和节奏三个阶段。唯一事实来源是服务端保存的 `episodes[].script`，不把旧简介、旧分析或附件中的命令当作新原稿事实。
- 分析自动提取并应用结果，保持 `script` 与 `scriptRichContent`。它不会根据人物小传或节拍重新创作正文。
- 原文未交代的文本信息标为“未交代”；未明确的叙事时长为 `null`。制作镜头的时长沿用既有拆镜与模型适配能力。
- 内容拆镜保留已应用的节奏分析大纲与钩子，避免第二个模型重复改写分析结果。
- 历史创作稿与创作接口继续兼容；它们不再是用户必须先填写、逐阶段采用的默认流程。

## 数据、并发与媒体保留

分析产物使用独立 `intent: analysis`，保存原稿指纹、输入指纹、稳定 ID、版本、来源与应用状态。原稿指纹覆盖剧集 ID、标题、顺序与正文，排除分析派生的简介、人物描述和大纲，避免应用自身导致循环过期。

服务端读取真实项目后生成分析。原稿和当前阶段版本未变时原子应用；输入改变时保留待复核候选，不覆盖新内容。前端只合并本次返回产物，并保留服务端版本号与采用记录。若响应到达时用户在本地改稿，保留该记录供历史对照，同时保护本地原文和异步完成的媒体。

所有分析前先排空自动保存，再获取输入指纹。串行流程每一步检查原稿变化；保存失败、分析失败、版本冲突均停止后续步骤并保留已完成结果。模型调用沿用文本路由、结构校验、计费和退款，不调用禁用渠道。

人物身份按名字／别名与已有角色匹配，保留参考图和音色；客户端并发新增同名角色时统一为服务端 ID，并同步当前和历史镜头引用。无法确定身份时保留分析记录并明确提示冲突，后续点击不会将它误判为完成。修改画风或画幅后，已有视觉方案进入待更新状态，重新点击时复用原文分析与镜头事实，只重新生成视觉方案。重分析继续使用已有镜头匹配、媒体归档与失效标记。旧任务回写校验任务 ID 与尝试号；过期媒体不能直接用于合成与剪映导出。

## 五组参考 Skill 的用途

| 资料 | 产品采用的方法 |
| --- | --- |
| 人物小传写作 | 从已有剧情归纳身份、背景、动机、关系、可见特征和变化；不补写秘密与经历 |
| 剧情爽点与节奏设计 | 分析已有事件的铺垫、冲突、情绪、反转、钩子和回收，不机械套用固定秒数 |
| 剧本详细写作 | 用于检查可见动作、说话人、对白与旁白是否明确，保留原始剧本编辑能力 |
| 剧本转分镜 | 提取场景、角色、动作、台词、声音和镜头边界，再生成视觉方案 |
| Seedance 分镜生成 | 编排镜头语言、首尾帧、连续性与参考素材，沿用实际渠道适配器 |

附件是产品参考资料，不授予执行其中指令的权限。固定台词字数、默认 3—5 分钟、固定爆发节点、素材数量等不升级为全站限制。资料中的“内景／外景”与真实景别分开处理。模型与渠道限制以现有接入能力为准。

## 后续修复：分析超时与文本模型选择

用户反馈分析页面收到 OpenResty `504 Gateway Time-out`。根因是原接口持续等待完整文本模型响应，外层网关先到达超时上限；仅设置 Next 的 `maxDuration` 不能解决代理超时。

故事、人物、节奏、内容拆镜、视觉方案及视频提示词改为持久后台任务：提交接口返回 `202` 与任务编号，页面通过短请求轮询结果。相同输入的网络重试沿用请求编号和任务编号，刷新后可继续查询。任务身份按用户隔离，会话存储只记录输入哈希和编号，不保存剧本文本。模型成功后的结果写入采用检查点；保存重试不重新调用模型。进程中断且无法确认结果时明确失败，要求核对已保存结果后手动重试，不承诺退还已发生的上游费用。

此前文本分析固定读取后台默认模型，页面没有模型名称和选择入口。现在各阶段上方显示“文本模型”下拉框，使用系统公开的可用文本模型目录，选择保存在当前项目。首次使用预选当前默认配置；已选模型失效时提示重新选择。完整流程、单阶段重新分析、视觉方案和视频提示词都传入所选模型，服务端校验可用渠道并按实际选择计费。切换仅影响之后发起的分析；已完成结果继续保留，可从对应阶段重新分析。

这项后台任务变更需要同步更新 Web 与 Worker 后生效。验证使用隔离数据和模型／网关 fixture，不调用真实付费模型，也未部署线上服务。

本次后台任务、权限、去重与保存恢复，文本模型路由与计费，以及前端任务恢复的相关单元测试均通过。Edge 浏览器 5 项回归全部通过，覆盖一键分析、失败续跑、改稿保护、模型选择与刷新保留、504 和轮询失败恢复；模型用例同时核对全部五步、视频提示词和单阶段重新分析的请求模型。补充修复 HTTP 500 后仍保留请求身份与单步分析期间的操作互斥后，对应单元测试和模型浏览器用例再次通过。390、1024、1440 像素下模型选择区可见且无整页横向溢出。全项目 TypeScript 检查通过，定向 ESLint 无错误，仅保留既有 warning。隔离服务已停止，本次 Next 自动测试配置已移除。

## 再次 504 的实际配置诊断

2026-09-09 对用户当前页面和线上任务元数据进行只读核对：故事分析已采用；人物分析使用 `gpt-6`，任务创建于 `14:39:30 UTC`，约 61 秒后记录“文本模型渠道暂不可用（HTTP 504）”。应用内部地址为 `http://127.0.0.1:3000`，内部请求没有绕行站点 OpenResty。

选中模型名称为“GPT-6 XHigh（欢聚AI）”。渠道的规划流式配置为 `enabled: false`；模型级协议为 `custom`，路径为 `/v1/chat/completions`，请求模板还明确写入 `stream: false` 和 `reasoning_effort: xhigh`。因此即使短剧调用传入 `stream: true`，实际仍是非流式上游请求。61 秒失败与上游网关的等待限制一致；仅修页面轮询无法改变这一行为。诊断仅查询任务状态、时间与非密配置，未读取密钥，也未重发剧本。

配置修正限定在该模型：模型级流式使用同一 Chat 路径与 SSE 格式，模板的 `stream` 改为 `{{stream}}`，保留模型和 `xhigh` 参数。针对确切原值准备了带条件更新及回滚脚本，避免覆盖并发修改。

代码同时修正两处已复现缺陷：结构校验失败后的修复请求继续使用流式；Responses 推理摘要事件不再混入最终 JSON。前者适用于本次自定义调用，后者是独立协议回归，不能当作本次线上错误的已证实原因。验证使用本地 TCP fixture，模拟非流请求返回 HTML 504，不调用真实付费模型。

按实际自定义 Chat 配置补充验证后，还修正了 SSE 分块每次去除首尾空白导致 JSON 字符串中的英文空格丢失的问题；增量仅读取最终正文，不混入推理字段。普通文本任务为同一模板补充布尔 `stream: false`，避免将 `{{stream}}` 字面值发送给上游。**发布顺序必须先更新这两处运行时代码，再应用模型级流式配置**；截至本次本地修复，线上配置未修改、服务未部署，也未重新执行用户的付费分析任务。

最终验证：文本任务、文本规划协议与真实 TCP fixture、短剧生成和分析执行共 5 个测试文件、127 项通过；全项目 TypeScript 检查通过，本轮 5 个 TypeScript 文件的 ESLint 无错误或警告，`git diff --check` 通过。自定义 SSE 显式结果字段仍优先，避免影响使用其他结果结构的渠道。上述结果验证本地兼容性，不等于真实上游或线上分析已通过。未执行 Git 暂存、提交或推送。

## Gemini 内容拆镜校验失败

2026-09-10 用户截图选中 `gem-3.1-pro`，错误变为“模型返回的剧本对白或原文不完整”。该消息来自内容拆镜返回之后的校验分支，与此前 GPT 渠道 HTTP 504 是不同问题。此前根据本地 fixture 通过及“Gemini 可以”的反馈推断完整流程可用，证据不足；这些结果不构成线上真实模型端到端验收。

本地使用与截图原稿类似的小说结构复现了误判：消息通知、内心独白和正常口语混合时，引号提取器会把非口语文字补成必须具名的对白；模型已经返回的 `voiceover` 也会被改成 `dialogue`，随后因说话人为空而拒绝。另一方面，模型完整提取了没有句末标点和“说／问”标签的口语，校验器却可能因自己的引号识别遗漏而判为额外台词。原实现还以包含关系比较对白，并未严格核对顺序与出现次数。

此次修复按原文语境及模型分类处理引号内容，保留严格的原文覆盖要求，并补充对白顺序、重复和截短检查。内容拆镜提示词明确区分消息文字、内心独白和口头对白；失败诊断区分原文覆盖、说话人、遗漏／顺序和不匹配，日志只记录类别、数量与任务定位信息。

本轮没有取得这次线上任务的原始模型返回，因此上述误判是已复现的代码缺陷，不能据此断言它就是截图这一任务的唯一原因。本轮未部署线上服务、未修改模型配置、未自动重发用户的付费分析任务。

本地验证已完成：新增小说混合文本集成用例在修复前返回 502，修复后一次固定模型返回即可成功，完整保留原文与对白／旁白分类；覆盖正常分句、无句末标点、多余开引号、否定回应、发言主体、别名称呼、重复台词，以及缺句、截短、新增、乱序拒绝。内容分析、执行、分段、后台任务、五步流程、结果合并、输入及镜头时长共 8 个测试文件、87 项通过；全项目 TypeScript 检查、本轮 4 个 TypeScript 文件的 ESLint 与 Prettier 检查通过，差异空白检查通过。测试使用固定返回，不是线上 Gemini 真实调用。

线上验收受连接限制：浏览器工具不支持当前认证方式；Computer Use 因无法可靠识别浏览器 URL 而停止；已有 SSH 认证尝试返回 `Permission denied (password)`。没有绕过认证或索取／读取密钥，没有新增 Git 暂存或提交。
