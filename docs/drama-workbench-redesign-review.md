# 短剧工作台：完整 Skill 创作流程

核对日期：2026-09-11。用户最新明确要求完整复刻提供的五组 Skill，并确认“完全按 Skill 创作，可调整剧情”。默认由 AI 从原稿自动提取输入和补足创作设定，不以前置表单要求用户手填。UI 视觉重设计后置，本轮实现工作流、完整产物及阅读入口。

## 当前流程

提供原稿 → 自动理解故事 → 完整人物小传 → 爽点与秒级节奏 → 详细改编剧本 → 标准分镜 → Seedance 提示词 → 审阅与视频制作。

故事理解是准备步骤。五个创作阶段分别执行对应 Skill 的完整主文件及配套指南，前序已采用的完整作品进入后序模型请求。人物基于全剧原稿，节奏、详细剧本及拆镜针对当前集。一键创作依次生成候选、保存、采用、再进入下一步；用户也可在单阶段生成、审阅和采用。

原稿仍保存在 episode.script 与 scriptRichContent。详细改编稿独立保存于已采用 script artifact 的 screenplay；getDramaProductionScript 选择有效改编稿供拆镜，过期时不会悄悄拿旧稿继续制作。skill.document 保存完整格式作品，另附补充假设、剧情调整和模型自查。正文不能被几句结构化摘要替代。

## 五组 Skill 的实际对应

| 阶段 | 完整来源 | 必需产物与制作映射 |
| --- | --- | --- |
| 人物小传 | 动态漫人物小传写作 Skill + 写作指南 | 逐角色五个模块；视觉特征、背景动机、反差触发、动作参数、声音细节、剧情关系和成长；结构化人物用于资产关联 |
| 节奏爽点 | 剧情爽点-节奏设计 Skill + 节奏设计指南 | 默认 180 秒框架、铺垫与释放、核心及小爽点、秒级冲突和情绪节点、留白、动态等级、三集闭环和十集节点 |
| 详细剧本 | 动态漫剧本详细写作 Skill + 剧本写作规范 | 完整场次正文、首次人物出场、动作与口型、三级动态、前中后景、音效字幕、制作说明；screenplay 作为拆镜原文 |
| 标准分镜 | 剧本转分镜 Skill + 分镜生成指南 | 基础信息、核心设定、前情、连续编号分镜、全部逐镜字段与特殊标注；完整报告与实际镜头数量和时长校验 |

来源的 10 份 Markdown 按原字节保存在 web/src/lib/server/drama-skills/sources，manifest.json 记录 SHA-256 与稳定版本，source-texts.json 随服务端静态构建打包。生产不访问用户桌面。客户端只读取轻量报告契约与来源元数据，不携带 Skill 全文。

完整请求中的源文件是方法资料：不执行其中的安装、上传、外部调用或付费命令，也不把示例人物与素材当成本项目事实。用户授权的自由改编优先于文档的忠实改编默认规则。缺失信息由 AI 明确列为假设；显式用户约束优先。默认时长、台词与节奏规范按 Skill 执行；用户指定不同创作目标时必须说明适配原因。

## 结果、复用与存储

- 新链使用 creation 产物及新方法版本，旧 analysis 记录仍可阅读，不冒充完整 Skill 创作结果。
- 原稿改变、上游采用稿改变或输入冲突时保留结果并停止后续；失败后从有效采用稿或已保存候选继续，采用失败不会再次生成同一候选。
- 下游收到完整人物、节奏和剧本作品；视觉请求还收到标准分镜报告、画幅及项目现有参考素材。
- 内容分段合并后分镜全局连续编号，保留每段完整正文与自查证据。模型自查在界面明确标记为模型声明；程序校验只证明必要结构及可检查格式，不代表实际创作质量、配音计时或观众测试已通过。
- 完整模式不允许归一化悄悄拆镜或改变时长，避免报告与实际镜头变成两套稿。内容拆镜在视频模型支持值与 Seedance 的 4 至 15 秒范围内选取时长；不兼容时在调用文本模型前明确报错。
- 当前素材清单属于文本建议，不自动生成或上传图片；未绑定供应商素材时不在实际提示词中伪造 @ 引用。用户可按使用提示制作素材后使用。
- 项目与历史写入容量统一为 16 MB，超过限制明确拒绝并保留现有数据，不自动删除旧版本或素材。

## 后续修复：分析超时与文本模型选择

用户反馈分析页面收到 OpenResty `504 Gateway Time-out`。根因是原接口持续等待完整文本模型响应，外层网关先到达超时上限；仅设置 Next 的 `maxDuration` 不能解决代理超时。

故事、人物、节奏、内容拆镜、视觉方案及视频提示词改为持久后台任务：提交接口返回 `202` 与任务编号，页面通过短请求轮询结果。相同输入的网络重试沿用请求编号和任务编号，刷新后可继续查询。任务身份按用户隔离，会话存储只记录输入哈希和编号，不保存剧本文本。模型成功后的结果写入采用检查点；保存重试不重新调用模型。进程中断且无法确认结果时明确失败，要求核对已保存结果后手动重试，不承诺退还已发生的上游费用。

此前文本分析固定读取后台默认模型，页面没有模型名称和选择入口。现在各阶段上方显示“文本模型”下拉框，使用系统公开的可用文本模型目录，选择保存在当前项目。首次使用预选当前默认配置；已选模型失效时提示重新选择。完整流程、单阶段重新分析、视觉方案和视频提示词都传入所选模型，服务端校验可用渠道并按实际选择计费。切换仅影响之后发起的分析；已完成结果继续保留，可从对应阶段重新分析。

这项后台任务变更需要同步更新 Web 与 Worker 后生效。验证使用隔离数据和模型／网关 fixture，不调用真实付费模型，也未部署线上服务。

本次后台任务、权限、去重与保存恢复，文本模型路由与计费，以及前端任务恢复的相关单元测试均通过。Edge 浏览器 5 项回归全部通过，覆盖一键分析、失败续跑、改稿保护、模型选择与刷新保留、504 和轮询失败恢复；模型用例同时核对全部五步、视频提示词和单阶段重新分析的请求模型。补充修复 HTTP 500 后仍保留请求身份与单步分析期间的操作互斥后，对应单元测试和模型浏览器用例再次通过。390、1024、1440 像素下模型选择区可见且无整页横向溢出。全项目 TypeScript 检查通过，定向 ESLint 无错误，仅保留既有 warning。隔离服务已停止，本次 Next 自动测试配置已移除。

## Gemini 内容拆镜校验失败

2026-09-10 用户截图选中 `gem-3.1-pro`，错误变为“模型返回的剧本对白或原文不完整”。该消息来自内容拆镜返回之后的校验分支，与此前 GPT 渠道 HTTP 504 是不同问题。此前根据本地 fixture 通过及“Gemini 可以”的反馈推断完整流程可用，证据不足；这些结果不构成线上真实模型端到端验收。

本地使用与截图原稿类似的小说结构复现了误判：消息通知、内心独白和正常口语混合时，引号提取器会把非口语文字补成必须具名的对白；模型已经返回的 `voiceover` 也会被改成 `dialogue`，随后因说话人为空而拒绝。另一方面，模型完整提取了没有句末标点和“说／问”标签的口语，校验器却可能因自己的引号识别遗漏而判为额外台词。原实现还以包含关系比较对白，并未严格核对顺序与出现次数。

此次修复按原文语境及模型分类处理引号内容，保留严格的原文覆盖要求，并补充对白顺序、重复和截短检查。内容拆镜提示词明确区分消息文字、内心独白和口头对白；失败诊断区分原文覆盖、说话人、遗漏／顺序和不匹配，日志只记录类别、数量与任务定位信息。
